# DS04 Draft

DS04 夹棍/隔山炮已完成当前项目最高 OS 口径下的工程审计与沙盒图人工校准。

## 继承关系

DS04 必须继承当前项目最高 OS：

- `hardened_fengji_line`
- 当前峰极确认与硬化规则
- 当前红蓝阵营状态机作为背景和审计字段
- `gap = 3`
- 同价最新

旧文档只参考 DS04 自身买卖逻辑，不参考旧 OS、旧 `GAP=4` 或旧 Runtime。

## 当前买卖逻辑

多头：

- K1 为阳线。
- K2 为阴线。
- K3 为阳线。
- K2 实体长度严格小于 K1/K3，且全长不大于 K1/K3。
- K1/K2/K3 均不得与前一根形成价格缺口。
- K3 收盘价突破 K1 最高价。
- K4 开盘做多。
- 初始防守为 K1/K2/K3 三根 K 线最低点。

空头：

- K1 为阴线。
- K2 为阳线。
- K3 为阴线。
- K2 实体长度严格小于 K1/K3，且全长不大于 K1/K3。
- K1/K2/K3 均不得与前一根形成价格缺口。
- K3 收盘价跌破 K1 最低价。
- K4 开盘做空。
- 初始防守为 K1/K2/K3 三根 K 线最高点。

## 防守升级

多头：

- 后续只接受更高的红极升级防守。
- 新红极必须 `> current_stop`，否则不采用。

空头：

- 后续只接受更低的蓝极升级防守。
- 新蓝极必须 `< current_stop`，否则不采用。

## OS 口径确认

旧 DS04 V3 FIX3 文档明确写明：OS 不作为开仓方向前置过滤，开仓方向由 K1/K2/K3 夹棍夺权结构决定。  
该口径已确认：DS04 是抄底摸顶型定式，不是阵营内顺势推进定式，因此不受红多蓝空开仓过滤约束。

这与当前最高 OS 不矛盾，因为 DS04 仍必须使用当前 OS 做峰极线、阵营背景、身份点、红极/蓝极防守升级和沙盒审计。
